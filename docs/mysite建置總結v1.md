## 2. 網站是什麼、誰會用

mysite 是個人影音內容網站：發表文章、影片（YouTube）、Podcast 音訊與一般頁面，另附一個「模擬」商店與管理後臺。整套系統在雲端 Linux 建置與測試，委託人只需要瀏覽器，不必在自己電腦安裝任何開發工具。

| 角色 | 用什麼 | 能做什麼 |
|---|---|---|
| 訪客 | 主站（公開網站） | 瀏覽文章、影片、Podcast、頁面；搜尋；訂閱 RSS；商店開啟時可以模擬購物 |
| 內容編輯者 | CMS（WordPress 後臺） | 撰寫、排程、發布、撤下內容；上傳圖片與音訊；預覽草稿 |
| CMS 管理員 | CMS（WordPress 後臺） | 編輯者能做的全部，加上選單、品牌設定與帳號管理 |
| 商店管理員（admin） | Laravel 管理後臺 | 管理商品、庫存、訂單、匯出、帳號停用；查看稽核紀錄 |
| 商店唯讀人員（viewer） | Laravel 管理後臺 | 只能檢視，不能修改 |
| 維運者 | 主機主控臺、GitHub | 部署、回復、備份還原、秘密輪替、故障處理 |

WordPress 帳號與 Laravel 後臺帳號是**兩套互不相通**的帳號；同名或同 email 也不會取得對方系統的權限。

## 3. 整體架構

### 3.1 兩個系統的分工

| 系統 | 負責 | 不負責 |
|---|---|---|
| **WordPress 7.1（CMS）** | 內容編輯、媒體上傳、草稿預覽、排程發布；以 REST API 提供公開內容；內容變動時主動通知主站 | 不直接對訪客提供公開頁面（CMS 前臺請求一律轉到主站） |
| **Laravel 13（主站）** | 所有公開頁面、搜尋、RSS、sitemap、模擬商店、管理後臺 | 不直接讀寫 WordPress 資料庫 |
| **MySQL 8.4** | 兩個資料庫（`mysite_wp`、`mysite_app`），各用自己的帳號 | 兩個帳號不能讀寫對方的資料庫 |

兩個系統只透過兩條管道整合：
1. **讀取**：主站呼叫 WordPress 的 REST API（`site-content/v1`）取得公開內容。
2. **通知**：WordPress 內容狀態改變時，送出帶 HMAC 簽章的「內容事件」給主站，主站立刻讓快取失效。

### 3.2 服務組成（Docker Compose）

| 服務 | 角色 |
|---|---|
| gateway | 唯一對外入口（Nginx）。依網域把請求分給主站或 CMS；登入頁的 POST 限流；正式環境負責 HTTPS |
| app-web | 主站的 Nginx，提供 Laravel 靜態檔並轉給 app-php |
| app-php | Laravel（PHP-FPM） |
| app-worker | Laravel 佇列工作 |
| app-scheduler | Laravel 排程（單一實例），負責保存期限清理、內容快取清理與排程心跳 |
| wp-web | CMS 的 Nginx（含 WordPress 靜態檔與上傳檔） |
| wp-php | WordPress（PHP-FPM） |
| wp-jobs | WordPress 背景工作：執行到期排程、排程補救、投遞內容事件、每分鐘對帳；有心跳檔與防重入鎖 |
| mysql | MySQL 8.4，不對外發布埠 |
| tools | 只在開發與測試使用（Composer、PHPUnit 等開發工具），正式環境沒有 |

### 3.3 網路與入口

- 三個網路：
  - **edge**：gateway 與兩個 Web 服務；只有 gateway 發布對外的埠。
  - **backend**：Web 與 PHP 服務；內部網路，不能連外。
  - **db**：PHP 服務與 MySQL；內部網路，不能連外。
- 對外入口：
  - **開發**：只綁在雲端 VM 本機的 8080（主站）與 8081（CMS）。
  - **測試**：18080、18081。
  - **正式**：只發布 80 與 443。
- **gateway 固定位址**：gateway 在 edge 網路固定使用 `.10`，其他容器只從 `.128` 以後動態分配。主站的 TrustProxies 與 CMS 的 real_ip 都**只信任 gateway 這一個位址**轉送的來源 IP。這樣主機本機或其他容器都無法偽造訪客 IP，登入限流與稽核紀錄才可信。
- **主站讀 CMS**：
  - 公開讀取走內部網路 HTTP。
  - 草稿預覽要帶服務帳號密碼，改走內部 HTTPS；憑證由本案自建的內部 CA 簽發，主站只信任這個 CA，不關閉 TLS 驗證。
- Nginx 每 10 秒重新解析服務名稱，避免容器重建後把流量送到舊 IP（施工中曾發生，已修正）。

### 3.4 資料存放

| 存放處 | 內容 |
|---|---|
| `mysql-data` 資料卷 | 兩個資料庫 |
| `wp-uploads` 資料卷 | WordPress 上傳的圖片與音訊 |
| `app-storage` 資料卷 | Laravel 的執行期檔案 |
| 秘密目錄（`.runtime/secrets/<環境>/`，不進 Git） | 所有密碼與金鑰，以檔案方式提供給需要的服務 |

重建容器不會遺失內容、媒體或 Session：已用自動測試實證（INF-06），強制重建全部服務後，文章、媒體檔與 Session 都還在。

### 3.5 環境

| 環境 | 用途 | 位置 |
|---|---|---|
| development | 開發與手動檢查 | Claude 雲端 VM |
| testing | 每次驗證都從零建立的乾淨環境 | Claude 雲端 VM 與 GitHub Actions |
| staging | 正式上線前的完整驗收 | 尚未建立（需要主機） |
| production | 正式站 | 尚未建立（需要主機與核准） |

## 4. 內容管理系統（WordPress）

### 4.1 四種內容

| 內容 | 主站網址 | 必填 | 選填 |
|---|---|---|---|
| 文章 | `/articles/{slug}` | 標題、內文 | 摘要、分類、標籤、封面圖 |
| 頁面 | `/pages/{slug}` | 標題、內文 | — |
| 影片 | `/videos/{slug}` | 標題、YouTube 網址 | 摘要、片長、分類、標籤、封面圖 |
| Podcast | `/podcasts/{slug}` | 標題、音訊（媒體庫檔案或核准網址） | 簡介、長度、分類、標籤、封面圖 |

- 四種內容都有「主站顯示」面板：
  - 「示例內容」：主站會加標示。
  - 「不在主站公開」：已發布也暫時下架。
- 欄位用 ACF 建立，設定檔以 JSON 版控。影片與 Podcast 是本案自製的內容型別。

### 4.2 其他內容結構

- 分類、標籤：主站有對應的彙整頁。
- 選單：主選單與頁尾選單兩個位置。內部連結自動轉成主站網址，外部連結只接受 https。
- 品牌：網站名稱、標語、作者簡介、社群連結（只接受 https）、Logo。
- 預設頁面：示例資料包含「關於」與「隱私說明」頁。隱私說明列出實際的 YouTube、音訊、託管與 cookie 使用方式（已有自動測試比對內容與實際行為）。

### 4.3 編輯器支援的區塊

- **保留語意與排版的區塊**：段落、標題（H2、H3）、圖片與圖說、引用、清單、連結、分隔線、程式碼、表格、封面。
- **會被移除或降級的內容**：
  - 嵌入區塊（只顯示網址）
  - 自訂 HTML、script、iframe、事件屬性
  - 短代碼
  - 只在 CMS 佈景主題生效的樣式

### 4.4 媒體上傳

- 只允許 jpg、jpeg、png、gif、webp、mp3、m4a、wav、ogg，單檔 32 MB 以內。
- 同時檢查副檔名、實際檔案內容與大小。雙副檔名（例如偽裝成圖片的 PHP）一律拒絕。
- 上傳資料夾內的檔案**不會被當成程式執行**。
- 媒體網址是公開的：知道網址的人都能讀取，包括只被草稿使用的檔案（WordPress 固有行為，已寫進編輯手冊）。

### 4.5 發布、排程、撤下

- **發布**：主站通常在 1 分鐘內更新。編輯者按儲存不必等主站，事件由背景工作送出。
- **排程**：到時間由 wp-jobs 自動發布，不需要有人瀏覽網站。
- **排程補救**：WordPress 把所有排程存在同一筆資料裡，「新增排程」與「執行排程」同時發生時，新事件可能被覆寫而遺失（合併後的 main CI 實際發生過）。wp-jobs 每一輪都會：
  - 補排遺失的發布事件，時間不變；
  - 補發已到期卻仍未發布的內容，發布時間仍記為原排程時間。
- **撤下**（改草稿、私人、密碼保護、移到垃圾桶、勾「不在主站公開」）：主站**最遲 60 秒**停止顯示正文。E2E 實測約 29 秒。
- 草稿、待審、未到時間的排程、私人、密碼保護、垃圾桶，一律不會出現在主站與公開 API。

### 4.6 草稿預覽

1. 編輯者在 CMS 按預覽。系統先建立這一版內容的**快照**，再簽發一張短效的**預覽票券**（預設 10 分鐘，最長 15 分鐘）。
2. 瀏覽器帶票券轉到主站。主站驗證簽章與時效後，記下這張票券的唯一編號，**同一張票券只能用一次**，重播即失效。
3. 主站建立只限預覽路徑的 Session cookie，清掉網址上的票券，再向 CMS 取回快照內容顯示。
4. 預覽頁不被快取、不被搜尋引擎索引、不進 RSS 或 sitemap，紀錄檔也不記票券。

### 4.7 CMS 前臺轉址

- CMS 網域的前臺請求（首頁、文章、分類、搜尋、Feed 等）一律 301 轉到主站對應網址，不透露非公開內容的存在。
- WordPress 內建的 sitemap 已關閉。sitemap 與 RSS 只由主站產生。

### 4.8 CMS 維護模式

- 換版遇到不相容的資料庫變更時，CMS 會與主站一起進入維護模式。
- 維護中，所有內容寫入與後臺編輯回 503 並附說明（共驗證 21 種入口，含管理員）；公開讀取與主站照常。
- wp-jobs 在維護中暫停排程、投遞與對帳，結束後自動恢復。
- 維運者可以手動開關與查詢狀態。部署腳本會在需要時自動開關。

### 4.9 CMS 帳號與安全

- **編輯者**只能管理內容，不能提升權限（已測試）。
- **管理員**在 staging／production 必須完成第二因素（Two Factor 外掛），開發環境只提示。
- **主站專用服務帳號**：只有讀取預覽的最小權限，以 Application Password 認證，只能走 HTTPS。
- 關閉 XML-RPC 與 pingback；未登入者不能列舉使用者；**留言全面關閉**。

### 4.10 WordPress 背景與管理指令（WP-CLI）

| 指令群組 | 用途 |
|---|---|
| setup | 冪等建立本外掛的資料表、角色與能力 |
| outbox | 列出、投遞、重播內容事件 |
| reconcile | 每分鐘對帳：補送漏掉的事件、偵測已刪除內容、清除過期預覽快照 |
| resync | 依內容 ID 強制重新同步 |
| schedule | 排程補救 |
| maintenance | CMS 維護模式開關與狀態 |
| keyring | 查看目前載入的簽章金鑰圈（只顯示 key ID 與狀態，不顯示金鑰） |
| seed | 建立示例資料（只限開發與測試環境，正式環境拒絕） |

## 5. 公開網站（Laravel）

### 5.1 頁面

| 網址 | 內容 |
|---|---|
| `/` | 首頁 |
| `/articles`、`/articles/{slug}` | 文章列表與內文 |
| `/videos`、`/videos/{slug}` | 影片列表與內容 |
| `/podcasts`、`/podcasts/{slug}` | Podcast 列表與內容 |
| `/pages/{slug}` | 一般頁面（例如關於、隱私說明） |
| `/categories/{slug}`、`/tags/{slug}` | 分類與標籤彙整 |
| `/search` | 站內搜尋（有限流） |
| `/feed.xml` | RSS |
| `/sitemap.xml` | 只列主站公開網址 |
| `/healthz`、`/readyz` | 健康與就緒檢查（只回 ok，不帶版本或路徑） |
| `/preview/exchange`、`/preview/view` | 草稿預覽（見 4.6） |

### 5.2 內容怎麼讀、怎麼快取

- **分層固定**：控制器 → 內容查詢服務 → 內容存放庫 → WordPress REST 用戶端。控制器不組網址、不持有密碼。
- **正文快取與可見性證明分開**：
  - 正文快取預設 300 秒。
  - 「這篇仍公開」的證明預設 30 秒有效，硬上限 60 秒。
  - 供應正文前必須持有未過期的證明，過期就向 CMS 重新確認。
  - 確認失敗回 503，**絕不回舊正文**；沒有任何「過期也照用」的備援。
- 列表、搜尋、首頁、RSS、sitemap、選單的快取時間都不超過可見性期限。收到內容事件時立即失效。
- 遇到上游錯誤時：找不到回 404；CMS 無法連線、逾時或資料格式不符回 503。錯誤頁一律正體中文並附隨機請求編號，不洩露技術細節。

### 5.3 內容呈現與安全輸出

- 富文字一律經同一個白名單淨化器處理後輸出。全站只有一個元件允許輸出 HTML，CI 會阻擋其他地方輸出未跳脫的 HTML。
- YouTube 以驗證過的 11 碼影片 ID、youtube-nocookie 播放器嵌入。**訪客按下播放前不連線 YouTube。**
- Podcast 播放器：
  - 顯示片長，提供下載替代連結，可以跳轉播放（支援分段傳輸）；
  - 音訊失效時顯示錯誤訊息並保留簡介。
- 圖片載入失敗時顯示明確的失效狀態，不留破圖。

### 5.4 SEO

- 每個公開頁 title 唯一，canonical 指向主站本頁，不指向 CMS。
- 預覽、後臺登入、搜尋結果頁帶 noindex。
- CMS 網址一律 301 到主站。

### 5.5 介面、無障礙與版面

- 正體中文介面。只用 Blade 樣板、原生 CSS 與 JavaScript（不使用 SPA 或 Tailwind）。
- **無障礙**：
  - axe-core 自動掃描首頁、文章、搜尋、商店、後臺登入，嚴重與重大問題為 0；
  - 只用鍵盤可以操作主選單與搜尋；
  - 第一個 Tab 是「跳到主要內容」；
  - 支援「減少動態效果」設定。
- **版面**：在手機 390、平板 768、桌面 1440 三種寬度下，sitemap 列出的全部公開頁都沒有水平溢位；200% 縮放下，首頁、列表、詳情、分類、標籤、搜尋、關於、404 等主要頁型也都通過；超長中文標題與超長網址都已測過。

### 5.6 Cookie 與快取隔離

- 匿名瀏覽公開頁**不設定任何 cookie**（實測 32 個公開頁）。
- CMS 與主站的登入 cookie 只限各自網域（host-only）、名稱不同，互不送出。
- 後臺、預覽、訂單頁的回應一律 `private, no-store`，不被共享快取保存。

## 6. 模擬商店

### 6.1 開關

| 設定值 | 行為 |
|---|---|
| `disabled`（預設） | 所有商店頁面與寫入回 404，導覽沒有商店連結，也不設 cookie |
| `simulation` | 開放模擬購物；每個結帳與訂單畫面都標示「模擬操作，不收款、不出貨」 |
| `real` 或其他值 | 啟動即拒絕；就算執行期被改成 real，也只回「僅限模擬」 |

### 6.2 流程

- 商品列表與商品頁 → 加入購物車 → 結帳 → 訂單頁 → 可取消。
- **購物車**只存在 Session，不另建資料表，避免兩個資料來源不一致；7 天未動清除。
- **訂單**：
  - 以無法猜測的查詢 token 加上「建立訂單的同一個 Session」才能查看，別人拿到網址也看不到；
  - 下單時保存價格快照，之後商品改價不影響既有訂單。

### 6.3 防護

- 不收卡號、真實地址、電話。送出這類付款欄位會被直接拒絕（422）。
- **結帳冪等**：重複送出不會重複下單；取消只回補庫存一次（狀態機加上資料庫唯一約束）。
- 庫存守恆：每次增減都寫入只能追加的異動紀錄。
- 篡改價格無效（以伺服器價格為準）。
- 購物車與結帳各有獨立限流。

## 7. 管理後臺

### 7.1 登入與帳號

- 登入網址：`/admin/login`。**沒有公開註冊**，帳號只能由維運者以指令建立，密碼只從檔案讀入。
- 支援兩步驟驗證（TOTP）與復原碼。staging／production 未完成兩步驟的帳號只能進入「帳號安全」頁。
- 忘記密碼：不論 email 是否存在都顯示同一訊息；重設連結 60 分鐘失效、用過即失效。正式郵件服務核准前，信件只寫進應用程式紀錄，不會寄出。
- **限流**：
  - 同 email 加同 IP，每分鐘 5 次；
  - 兩步驟驗證每分鐘 5 次；
  - 整個登入相關路由每 IP 每分鐘 60 次；
  - gateway 另外對登入 POST 限流。

### 7.2 權限

| 動作 | admin | viewer |
|---|---|---|
| 檢視儀表板、商品、訂單、稽核、使用者 | ✓ | ✓ |
| 新增／編輯商品與規格、調整庫存 | ✓ | ✗（403） |
| 取消訂單 | ✓ | ✗ |
| 匯出訂單 CSV（留稽核、不含 token） | ✓ | ✗ |
| 停用／啟用其他帳號（不能停用自己） | ✓ | ✗ |
| 兩步驟驗證、改自己的密碼 | ✓ | ✓ |

- 權限一律在伺服器端判斷，介面隱藏按鈕只是輔助。
- 缺少 CSRF token 的寫入會被拒絕（419）。
- 寫入與匯出各有限流。

### 7.3 功能

- 儀表板。
- 商品、規格、庫存調整：增減必須附備註，調整後不得為負。
- 訂單列表、詳情、取消、匯出。
- 使用者清單與停用：停用立即生效，該帳號所有 Session 一併刪除。
- 稽核紀錄：權限、商品、庫存、訂單、匯出、使用者、登入與兩步驟事件都會記錄，內容先去除秘密，IP 只留前綴。
- 帳號安全頁。

### 8.1 資料保存期限（專案預設，非法定期限）

| 資料 | 保存方式 |
|---|---|
| 模擬訂單 | 30 天後匿名化（清除 token、Session 綁定與測試代號，保留金額與件數供統計） |

## 9. 安全設計

| 面向 | 做法 |
|---|---|
| 秘密管理 | 秘密只放在不進 Git 的秘密目錄，以檔案提供給需要的服務（`*_FILE`）。檔案要存在、非空、權限不得過寬，正式環境缺秘密就拒絕啟動。WordPress 拿不到 Laravel 的資料庫密碼，反之亦然。秘密不得寫進紀錄、證據或截圖：每次驗證都拿實際秘密值，逐位元組比對所有結果檔、證據與截圖 |
| 簽章金鑰輪替 | 內容事件與預覽票券各有一個「金鑰圈」，每把金鑰都有 key ID。輪替分三期：新增（只接受）→ 啟用（改用新鑰簽章，舊鑰仍接受）→ 撤舊（舊鑰簽的一律拒絕）。在 testing 環境實跑過三種輪替。Laravel 的 APP_KEY 也能先保留舊鑰再撤除 |
| 網路隔離 | 資料庫與 PHP 服務都在不能連外的內部網路；只有 gateway 對外 |
| 來源 IP 可信 | 只信任 gateway 固定位址轉送的 X-Forwarded-For，偽造無效 |
| 安全標頭 | 禁止 MIME 猜測、限制 iframe 嵌入、Referrer-Policy、Permissions-Policy（關閉相機、麥克風、定位、付款）；正式環境可設 HSTS |
| PHP 設定 | 關閉 upload progress、不暴露 PHP 版本、不顯示錯誤、記錄錯誤；doctor 每次經 HTTP 實際讀回驗證 |
| 敏感檔案 | `.env`、`.git`、`vendor`、`composer.json`、WordPress 設定檔、除錯紀錄等一律不可下載 |
| 存取紀錄 | Nginx 紀錄不記錄網址查詢字串，避免預覽票券留在紀錄裡 |
| 內部端點 | 診斷與部署狀態端點不能經由 gateway 從外部取得（部署狀態另需唯讀權杖） |
| 弱點掃描 | 每次驗證都掃描：映像（Trivy，只要有已可修補的高風險或重大弱點就擋下）、Composer 與 npm 依賴、WordPress 核心與外掛。另有每週排程的依賴稽核 |
| 秘密掃描 | 規則式掃描所有追蹤檔與證據；CI 另以 gitleaks 掃描完整 Git 歷史 |
| 版本鎖定 | 所有映像以 digest 固定，所有 GitHub Action 以完整 SHA 固定，下載檔案以 SHA-256 核對 |

## 10. 部署、備份與維運

### 10.1 發布流程

1. **CI 驗證**：main 上的 commit 通過 CI。
2. **release（建置候選版）**：建置正式映像 → 弱點掃描 → 推送到 GitHub 套件庫（GHCR）→ 產生候選版。
   - 自動發布**預設關閉**，因為推送 GHCR 可能佔用付費額度。
   - 要由委託人在 repo 設定 `MYSITE_AUTO_RELEASE=true` 才會自動執行；在 main 上手動觸發則不受影響。
3. **deploy-staging**：在受保護的 GitHub environment 中，用 Ed25519 私鑰簽署發布清單，給新的遞增序號，發布到 staging 頻道。
4. **主機下載**：主機每約 5 分鐘主動下載一次，用公鑰驗簽，並檢查格式、環境、序號（防重播）與時效（24 小時）。主機只放公鑰。
5. **換版**：主機以固定 12 步驟換版（見 10.2）。
6. **確認**：GitHub 端輪詢主機的部署狀態，並做外部 HTTPS 冒煙測試。
7. **deploy-production**：需要核准，而且只接受 staging 目前那一批映像 digest；不重新建置。

### 10.2 主機換版的 12 個步驟

1. 驗證清單（驗簽、schema、環境、序號、時效）
2. 取得部署鎖
3. 記錄 pending；同一清單最多重試 3 次（暫定）
4. 檢查磁碟空間（至少 3 GB，暫定）與憑證
5. 下載所有映像並逐一核對 digest
6. 部署前備份；備份失敗就不換版
7. 判斷資料庫變更等級：向後相容（none、expand）自動處理；不相容（contract、breaking）要有核准參照
8. 暫停會寫資料的工作；不相容變更另開主站與 CMS 維護模式
9. 執行資料庫遷移與 WordPress 更新
10. 換版並等待全部服務就緒，再關閉維護模式
11. 冒煙測試；不符就自動回到上一版
12. 記錄啟用版本與歷史

部署從不執行刪除資料卷、清空資料庫、自動退回遷移或資料還原。

### 10.3 回復

- 以「新的、更大序號」的已簽章回復清單，把程式換回本主機曾成功啟用、資料庫相容的版本。
- 已撤銷的映像 digest 不能再部署或回復。

### 10.4 備份與還原

- **工具**：restic（加密、去重複）。備份目的地放在與主機不同的雲端空間（異地）。
- **備份內容**：兩個資料庫的一致性匯出、刪除紀錄、WordPress 媒體、部署狀態，以及含 SHA-256 的清單。秘密不在備份內，要另存於委託人的密碼管理器。
- **排程**（以主機的 systemd timer 執行）：

  | 項目 | 頻率 | 保留 |
  |---|---|---|
  | 主站資料 | 每小時 | 48 小時，加上 30 日備 |
  | CMS 資料與媒體 | 每日 | 30 日備，加上 12 月備 |
  | 深度檢查 | 每週 | 30 日備 |
  | 臨時備份 | 每次部署與回復前 | 30 日備 |

- 清除舊備份的動作預設只「預覽」，確認不會誤刪後，經核准才實際執行。
- **還原演練**：
  - 永遠還原到全新、隨機命名、不接外部網路的隔離環境，不能直接還原到 staging 或 production；
  - 檢查完整性、各狀態筆數、未公開內容仍未公開、媒體引用都存在；
  - 已在 CI 以真實 MySQL 加 restic 實測（測試資料量），還原時間約 13 秒。
- **目標**（非保證）：內容最多遺失 24 小時、模擬訂單最多 1 小時；主站 4 小時內恢復。

### 10.5 秘密輪替

可輪替的項目：主站與 CMS 的資料庫密碼、WordPress salts（會讓所有人重新登入）、主站讀取 CMS 用的服務帳號密碼（Application Password）、事件簽章金鑰、預覽簽章金鑰、Laravel APP_KEY。

- 每次輪替都需要核准參照。
- 新值只寫進秘密檔，從不輸出。
- 失敗會自動回到原狀。

### 10.6 HTTPS

- gateway 有兩種模式：bootstrap（首次申請憑證）與 https。
- 憑證由 Certbot 申請，主機有自動續期的 timer。
- 正式環境的 Session cookie 一律 Secure。

### 10.7 維運腳本（全部支援說明參數，退出碼統一）

| 類別 | 腳本 |
|---|---|
| 雲端開發 | 預檢、首次建置（冪等）、啟動、健康檢查（doctor）、新會話恢復、進度保存、Composer 包裝、依賴下載、開發便利指令 |
| 部署 | 主機開通、部署前檢查、下載清單、驗證清單、換版、回復、冒煙測試 |
| 維運 | 備份、隔離還原演練、秘密輪替 |

退出碼統一定義：0 成功、10 參數錯、20 缺外部前置、21 建議改用 GitHub Actions、30 測試失敗、40 禁止的操作、50 部署或還原未完成。

## 11. 開發流程與自動化測試

### 11.1 雲端開發

- 全部在雲端 Linux VM 進行。
- 新會話啟動時，自動讀取進度與狀態，並恢復開發服務，不重設任何資料。
- 首次建置（bootstrap）會一次建立秘密、映像、資料庫、WordPress 安裝、Laravel 資料表與示例資料。重跑不會重設資料或金鑰，且有自動測試驗證這點。
- 測試資料庫與開發資料庫完全隔離。施工中曾發生測試誤清開發資料庫，之後加了兩道防護。

### 11.2 一次完整驗證包含什麼

依序執行：
1. 靜態檢查（語法、說明參數、狀態檔、忽略規則、秘密掃描、HTML 輸出、文件參照、版本鎖定、workflow 語法、完整歷史秘密掃描）
2. 從零建立 testing 環境
3. 第二次建置冪等檢查
4. doctor
5. PHPUnit
6. WordPress 契約測試
7. 真實瀏覽器 E2E
8. 部署工具測試
9. 治理檢查與弱點掃描
10. 彙整證據

內容站（商店關閉）與模擬商店兩個範圍各跑一次。

### 11.3 測試種類與數量（最近一次 CI）

|---|---|---|
| PHPUnit | 356 項、3,448 個斷言 | 內容整合、快取與可見性、事件驗簽、預覽、商店、後臺權限、資料保存、設定驗證、代理信任；行覆蓋率 94.83%（門檻 70%） |
| WordPress 契約測試 | 31 項 | API 結構與參數上限、不回傳敏感欄位、非公開狀態隱藏、權限提升、區塊語意、事件簽章與重試、對帳補漏、預覽票券、排程與排程補救、維護模式、真實來源 IP、金鑰圈、XML-RPC 與使用者列舉、示例資料只限測試環境 |

### 11.4 GitHub Actions workflows

| Workflow | 觸發 | 作用 |
|---|---|---|
| ci | 推送 main 或工作分支、對 main 的 PR、手動 | 完整驗證兩個範圍；標記 WIP 的施工快照只跑靜態檢查 |
| sandbox | 手動，或推送 `sandbox/` 開頭的分支 | 雲端 VM 不能用時的備援驗證；也可以在乾淨環境重新產生 lockfile 並核對 |
| release | main 的 CI 成功後（需開關）、手動 | 建置、掃描、推送映像，產生候選版 |
| deploy-staging、deploy-production | 只能手動，在受保護的 environment 中執行 | 簽署並發布清單、確認部署結果 |
| dependency-audit | 每週一 02:37（台北時間）、手動 | 依賴與映像稽核報告 |

- PR 與 fork 觸發的 workflow 只有唯讀權限，拿不到任何正式秘密。
- 已實際確認：備援流程 sandbox 在 main 上整輪通過；它在乾淨環境重新產生的 lockfile 與 repo 中的版本逐位元組相同；release 被開關擋下。

### 11.5 驗收登錄表與證據

- 規劃書的 90 項驗收加上執行契約的 6 項，共 96 項，逐項對應到實際測試。
- 只有實際跑過的才記 PASS。CI 的通過不能代替真實主機上的驗收，這類項目維持「外部阻擋」，並保留 CI 證據。
- 每次 CI 結果都匯入 repo（`docs/evidence/`），可追溯 run 編號、受測 commit、lockfile 雜湊。報告提交與受測程式提交分開。

## 13. 重要工程決策（摘要）

| 決策 | 理由 |
|---|---|
| 單一 repo，`app/` 放 Laravel、`wp/` 放 WordPress 自製程式 | WordPress 核心、第三方外掛、vendor 不進 Git，建置時依雜湊取得 |
| 映像來源可在 Docker Hub 與 ECR Public 之間切換（相同 digest） | 避開 Docker Hub 匿名下載限流，內容不變 |
| 映像只由統一的建置腳本產生，Compose 只引用映像 | 雲端 VM 與 GitHub Actions 走同一條路徑 |
| 秘密以檔案提供，並驗證權限與內容 | 不進環境變數明文，不進 Git |
| 正文快取與可見性證明分開，不設過期備援 | 撤下的內容 60 秒內一定消失 |
| 事件 HMAC 與預覽票券使用不同金鑰，並支援金鑰圈 | 用途分離、可平順輪替 |
| 唯一的 HTML 淨化器與唯一的 HTML 輸出元件 | 防止跨站腳本攻擊 |
| 購物車只存在 Session | 避免兩個資料來源不一致 |
| 儲存與 API 一律使用 UTC，畫面才顯示台北時間 | 跨日排程不會偏移 |
| 測試只連 MySQL 測試庫，並強制檢查庫名 | 不用 SQLite 冒充，也不會誤清開發資料 |

完整內容見 `docs/架構決策.md`。

## 15. 已知限制與尚未完成的項目

**需要真實主機才能完成的驗收**：
- HTTPS 憑證與自動續期；
- 主機重開機後服務自動恢復；
- 停止開發環境不影響正式站；
- 告警送達；
- 異地備份與正式還原；
- 30 天可用性觀察；
- 正式管理員親自登記第二因素。

**已知限制（已記錄）**：
- YouTube 與音訊的實際播放：雲端 VM 連不到外部影音服務，只驗了嵌入規格，要在 staging 用瀏覽器確認。
- Two Factor 外掛 0.17.0 以明文存放 TOTP 秘鑰（外掛本身的行為）。
- 媒體網址知道就能讀，包含草稿使用的檔案（WordPress 固有行為）。
- 金鑰圈「啟用後最晚 24 小時內撤舊」（暫定），目前由文件與紀錄管理，程式不自動強制。
- WordPress 外掛弱點資料來自一個公開 API，該服務沒有明確條款。若要更完整的資料，可以申請 Wordfence 的免費 API 金鑰。
- CMS 事件 outbox 與對帳索引目前不會自動清理（待決定）。
- 正式郵件服務尚未核准：密碼重設信目前只寫進紀錄，不會寄出。

## 16. 上線前要準備的事

| 項目 | 建議 |
|---|---|
| 主機 | Linux VPS，Ubuntu 24.04 LTS、x86_64。建議 2 核、4 GB 記憶體、80 GB 硬碟，選東京機房。例如 Vultr 一般方案，官網標價約每月 20 美元（以當日價格為準）。初期可以先一台同時放 staging 與正式站，預算允許再分開 |
| 防火牆 | 只開 80、443 |
| 網域 | 主站與 CMS 兩個名稱（例如 `www.` 與 `cms.`），指向主機 IP |
| 異地備份 | 與主機不同公司的物件儲存，例如 Backblaze B2（約每 TB 每月 6.95 美元，前 10 GB 免費；以當日價格為準）。備份密碼另存於密碼管理器 |
| 告警通道 | 例如一個 email |
| GitHub 設定 | 在 environments 建立 staging／production 的發布簽章私鑰與部署狀態權杖（不要貼進對話）；決定是否開啟自動發布 |
| 核准 | 正式發布核准；管理員親自登記第二因素；核對個資申請期限的法規現行版本 |

準備好之後，依 `docs/runbooks/主機開通.md` 的 P0～P8 進行，全程在供應商的網頁主控臺與 GitHub 網頁完成，不需要本機工具。

| 事件 | 影響 | 處置 |
