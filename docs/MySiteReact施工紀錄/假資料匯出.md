## 0. 摘要

- 這支 artisan 指令在 Laravel 行程內以 HTTP kernel 直接呼叫公開 API `/api/v1/*`（不經網路、不經 gateway），把**示例內容**轉成前端「假資料模式」用的 JSON，並產生對應的合成圖檔與音檔。
- 轉換集中在一個明確的假資料轉換層（`app/app/Domain/Content/Mock/MockTransformer.php`）：只收 `is_sample: true`、媒體網址改寫為 `/mock-media/…`、植入哨兵字串。轉換前後都以契約驗證。
- 正式來源政策（`app/app/Domain/Content/Media/MediaPolicy.php`、`app/app/Support/Html/Sanitizer.php`）完全沒有改動，也沒有為假資料放寬（M-19）。
- 任何一步失敗（遇到非示例內容、API 非 200、契約不符……）都會中止且**不寫入任何檔案**；輸出位置已有內容時也直接中止，工具本身不覆寫、不刪除任何檔案。

## 1. 怎麼執行

### 1.1 前提
- 環境：`APP_ENV` 必須是 `local`、`development` 或 `testing`；staging／production 一律拒絕。
- 需要開發相依套件 `osteel/openapi-httpfoundation-testing`（契約驗證用；development 容器已安裝）。
- WordPress 要有已發布的示例內容（開發環境的示例資料即可），且**所有**公開內容都必須是示例內容：只要首頁、列表、單篇、頁面、分類、標籤或搜尋結果裡出現任何一筆 `is_sample` 不是 `true`，整批中止。

### 1.2 指令（在 repo 根目錄）

```bash
source scripts/lib/common.sh && source scripts/lib/compose.sh && ms_compose_prepare "$PWD" development
ms_compose exec -T -u www-data app-php php artisan content:export-api-mocks --out=storage/app/mock-export
```

- `--out` 必填。相對路徑以 Laravel 專案根（容器內 `/var/www/app`，即 repo 的 `app/`）為準。上例的輸出位置是 `app/storage/app/mock-export/`，已被 `app/storage/app/.gitignore` 排除，不會進 Git。
- `<out>/mocks/` 與 `<out>/public/mock-media/` 必須不存在或是空目錄。要重新匯出時，請指定新的目錄，或自行移除舊的匯出結果。
- `php artisan content:export-api-mocks --help` 會列出參數與結束碼。

### 1.3 結束碼（沿用 docs/執行契約.md 的 exit code 契約）

| 結束碼 | 意義 |
|---|---|
| 0 | 成功 |
| 10 | 參數錯：沒給 `--out`、`--out` 不是目錄、輸出位置已有內容 |
| 20 | 缺外部前置：找不到契約驗證套件或契約檔 |
| 30 | 功能失敗：某個端點不是 200、回應或轉換結果不符合契約、找不到有結果的搜尋 |
| 40 | 禁止的操作：遇到非示例內容、在不允許的環境執行 |

## 2. 取資料的順序

1. `GET /api/v1/site`
2. `GET /api/v1/home`
3. `GET /api/v1/articles`、`/videos`、`/podcasts`（各取第 1 頁）
4. 第 3 步列表中每一篇的單篇（路徑取自摘要的 `path`，保留百分比編碼）
5. `GET /api/v1/pages/{slug}`：從網站資訊的主選單與頁尾選單中，`external: false` 且網址為 `/pages/{slug}` 的項目。回 404 的頁面略過，記在 manifest 的 `skipped`；選單裡完全沒有頁面連結時也會記一筆
6. 分類與標籤總覽 `GET /api/v1/categories/{slug}`、`/tags/{slug}`（不帶 `type`）：slug 取自第 4 步單篇的 `categories`、`tags`
7. `GET /api/v1/search`（空查詢）
8. 一個有結果的搜尋：先試 `q=示例`，沒有結果再試第一篇內容標題的前 20 字；都沒有結果就中止（結束碼 30）

## 3. 輸出結構

```
<out>/
├─ mocks/
│  ├─ manifest.json            每個檔對應的 API 路徑、operation、狀態碼、請求時間（UTC）、雜湊
│  ├─ site.json                GET /api/v1/site
│  ├─ home.json                GET /api/v1/home
│  ├─ articles/_index.json     GET /api/v1/articles（第 1 頁）
│  ├─ articles/<slug>.json     GET /api/v1/articles/{slug}
│  ├─ videos/_index.json、videos/<slug>.json
│  ├─ podcasts/_index.json、podcasts/<slug>.json
│  ├─ pages/<slug>.json        GET /api/v1/pages/{slug}
│  ├─ categories/<slug>.json   GET /api/v1/categories/{slug}（總覽）
│  ├─ tags/<slug>.json         GET /api/v1/tags/{slug}（總覽）
│  ├─ search/empty.json        GET /api/v1/search
│  ├─ search/results.json      GET /api/v1/search?q=…（有結果）
│  └─ edge/<情境>.json         合成邊界案例（第 5 節）
└─ public/
   └─ mock-media/
      ├─ mock-cover.png        封面與 og_image 共用（16×9 單色）
      ├─ mock-logo.png         網站標誌（8×8 單色）
      ├─ mock-inline.png       正文 content_html 內的圖片（16×9 單色）
      └─ mock-audio.wav        Podcast 音訊（PCM 16 位元、單聲道、8000 Hz、0.5 秒靜音）
```

- 檔名規則：slug 符合 `^[a-z0-9][a-z0-9-]{0,99}$` 時原樣使用；其餘（中文、過長、其他字元）改用 `_slug-<sha256 前 16 碼>`。列表固定叫 `_index.json`；底線開頭的名稱不會與 slug 衝突。實際對應一律以 manifest 為準。
- 所有 JSON 以 UTF-8、縮排、不跳脫中文與斜線輸出，結尾一個換行。
- 合成媒體全部由程式現場產生（PNG 手寫檔案結構、WAV 手寫 RIFF 標頭），不下載、不複製任何外部或 WordPress 上的檔案，沒有授權疑慮。

### 3.1 manifest.json 欄位

| 欄位 | 說明 |
|---|---|
| `format` | 固定 `mysite-api-mocks/1` |
| `generated_at`、`app_env` | 產生時間（UTC）與執行環境 |
| `sentinel` | `MSMOCK-7F3A9C1E` |
| `contract` | 契約檔位置、`info.version`、檔案 sha256（前端可比對自己保存的契約副本） |
| `rules` | 改寫欄位、保留欄位、植入哨兵的欄位 |
| `search_query` | 第 2 節第 8 步實際使用的查詢詞 |
| `skipped` | 略過的請求與原因 |
| `files[]` | `file`（相對匯出根目錄）、`kind`（`export` 或 `edge`）、`scenario`（僅 edge）、`description`（僅 edge）、`api_path`（前端會送出的路徑，含查詢字串與百分比編碼）、`requested_at`（UTC；edge 為 null）、`operation_id`、`operation_path`、`method`、`status`、`sha256` |
| `media[]` | `file`、`url`、`mime`、`bytes`、`sha256`、`description` |

`files[].file` 與 `media[].file` 都相對於匯出根目錄，正好對應前端儲存庫根目錄的 `mocks/` 與 `public/mock-media/`。

## 4. 轉換規則（假資料轉換層）

| 規則 | 做法 |
|---|---|
| 只收示例內容 | 網站資訊與每一筆內容（首頁各區塊、列表、單篇、頁面、分類／標籤總覽、搜尋結果）的 `is_sample` 必須是 `true`，否則中止（結束碼 40）。WordPress 讀不到時 `/api/v1/site` 會回後備資料（`fallback: true`、`is_sample: false`），同樣中止。依據：v1 §4.4「不得放未公開稿件或委託人的創作原文」 |
| 圖片網址 | 封面 `cover.url` → `/mock-media/mock-cover.png`；網站 `logo.url` → `/mock-media/mock-logo.png`；`alt`、`width`、`height` 不變；原本是 null 的維持 null |
| `seo.og_image` | 不是 null 時 → `/mock-media/mock-cover.png` |
| Podcast 音訊 | `audio_url` 不是 null 時 → `/mock-media/mock-audio.wav`，`audio_mime` 同時改成 `audio/wav`；`audio_unavailable: true` 的維持 null |
| 正文圖片與 CMS 連結 | `content_html` 內每個 `<img>` 的 `src` → `/mock-media/mock-inline.png`；指向 CMS（主機名與 WP_PUBLIC_URL 相同，不分協定、含 `//主機/` 寫法與主機名尾端的點，或含 `/wp-content/uploads/`）的 `<a href>` 與 `<blockquote cite>` 也改指同一個合成檔（例如圖片設成「連結到媒體檔」）；其他屬性與標記不動 |
| YouTube | `video.watch_url`、`video.embed_url` 保留原值：前端點擊前不連線，E2E 會攔下 |
| 哨兵字串 | `site.tagline`、每筆內容的 `excerpt`、每個回應的 `seo.description` 開頭加 `MSMOCK-7F3A9C1E`（原值非空時中間隔一個半形空白）；`content_html` 最前面加一個純文字段落 `<p>MSMOCK-7F3A9C1E</p>` |
| 契約驗證 | API 原始回應先以契約驗證；轉換後的每一份 JSON 再以同一份契約、依 operation path 與狀態碼 200 驗證一次；不合即中止 |
| 自我檢查 | 轉換後逐欄確認：沒有 `is_sample` 不是 `true` 的物件；所有圖片、`og_image`、`audio_url`、正文 `<img src>` 都只指向實際產生的合成檔；`excerpt`、`content_html` 以哨兵開頭。另做全文檢查：整份輸出不得殘留 CMS 主機名或 `/wp-content/uploads/`，不論在哪個欄位，否則中止 |

為什麼 `seo.description` 也加哨兵：零篇列表、空查詢搜尋這類回應沒有任何內容物件，只靠 `excerpt` 就會有檔案不含哨兵。加在 `seo.description` 讓**每一份**假資料檔都帶哨兵，前端建置產物或映像只要混進任何一份，FE-09 的全文搜尋都抓得到。

`content_html` 的處理方式：以 PHP 內建的 `Dom\HTMLDocument` 解析（與 Sanitizer 產生輸出時用的是同一個序列化器），只替換既有 `<img>` 的 `src` 值與指向 CMS 的連結，再新增一個以 `textContent` 寫入的 `<p>`，不新增其他元素或屬性。開發環境實跑時逐篇比對：轉換結果等於「哨兵段落＋原文（只換了 `src`）」，16 篇全部一致。

正式政策沒有放寬：`/mock-media/…` 是相對路徑，正式的 `MediaPolicy` 與 `Sanitizer` 都不接受（測試有斷言）。轉換只發生在匯出工具裡，正式 API 的輸出不受影響。

## 5. 合成邊界案例

邊界案例由 `app/app/Domain/Content/Mock/MockEdgeCases.php` 以寫死的合成文字產生（標 `is_sample: true`，不取自 WordPress）。為了讓形狀與真實 API 完全一致，內容 DTO 一律經正式的 Sanitizer、MediaPolicy（經 `PublicApiPresenter`）與 `PageMetaFactory` 產生，外層包裝比照 `PublicContentController`；之後與真實匯出走同一個轉換層與契約驗證，所以同樣帶哨兵、媒體同樣改寫。

| 檔案（`mocks/edge/`） | 情境 | 產生方式 | `api_path` |
|---|---|---|---|
| `long-title.json` | 超長中文標題（220 字）；正文含一張圖片 | 合成標題 | `/api/v1/articles/msmock-edge-long-title` |
| `long-url.json` | 超長網址（約 700 字元、無空白），出現在摘要與正文連結 | 合成網址（example.com） | `/api/v1/articles/msmock-edge-long-url` |
| `no-cover.json` | 無封面（`cover`、`seo.og_image` 皆為 null） | 不給封面 | `/api/v1/articles/msmock-edge-no-cover` |
| `empty-list.json` | 零篇列表（文章列表第 1 頁、`total` 0、`total_pages` 0） | 空的分頁結果 | `/api/v1/articles` |
| `video-unavailable.json` | 影片 ID 不合法（`video_unavailable: true`，三個影片欄位為 null） | 把不合法 ID 交給正式 MediaPolicy 判定 | `/api/v1/videos/msmock-edge-video-unavailable` |
| `audio-unavailable.json` | 音訊不可播（`audio_unavailable: true`，簡介照常提供） | 把不在允許清單的來源交給正式 MediaPolicy 判定 | `/api/v1/podcasts/msmock-edge-audio-unavailable` |
| `chinese-slug.json` | 中文 slug，`path` 與 `api_path` 為百分比編碼 | 合成中文 slug | `/api/v1/articles/%E7%A4%BA%E4%BE%8B…`（完整值見 manifest） |
| `slug-200.json` | slug 恰為 200 字 | 合成 ASCII slug | `/api/v1/articles/msmock-edge-slug-200-…`（完整值見 manifest） |

- `empty-list.json` 的 `api_path` 與真實匯出的 `articles/_index.json` 相同，請以 manifest 的 `kind: "edge"` 與 `scenario` 區分，當成「另一種情境」使用，不要覆蓋真實列表。
- 每個情境產生後會自我檢查（例如確認正式政策真的把影片判為不可播），不符就中止，代表正式政策或 API 形狀已經變了。

## 8. 前端 F3 如何匯入（原則）

由施工者在前端儲存庫（MySiteStorage）的 F3 進行，本工具不碰前端儲存庫：

1. 把匯出根目錄下的 `mocks/` 整個複製到前端儲存庫的 `mocks/`，`public/mock-media/` 整個複製到前端儲存庫的 `public/mock-media/`（目錄結構原樣保留，manifest 一併帶過去）。
2. 假資料讀取器以 manifest 的 `api_path`（`kind: "export"`）對應檔案；邊界案例（`kind: "edge"`）供元件測試與 E2E 情境使用。
3. 前端 CI 以同一份契約副本再驗證一次（v1 §6.8 第 5 步），並可比對 manifest 的 `contract.sha256` 與自己保存的契約副本。
4. 兩個目錄都是受保護路徑（v1 §6.2），正式映像不得含有它們（v1 §6.9、M-17）；FE-09 以哨兵字串 `MSMOCK-7F3A9C1E` 在 `.next/` 產物與最終映像全文搜尋，零命中才通過。
5. 假資料只放示例內容；更新假資料時一律重新執行本工具，不要手改 JSON 放進真實稿件。

## 9. 已知限制與待確認

1. **200 字 slug 在真實 API 拿不到**：`Slug::toApi` 對小寫英數與連字號的 slug 只接受 1～190 字（191～200 字一律當不存在而回 404；已百分比編碼的形式可到 200 字元），而路由與契約允許到 200 字。`slug-200.json` 符合契約，但真實 API 目前不可能回傳這種回應。已處理：契約說明補正 slug 的實際規則（`docs/公開API契約.md` 第 3 節）；`Slug` 規則與 Blade 相同，本案不改。
2. Podcast 的 `duration_seconds` 保留原值，合成 WAV 只有 0.5 秒；畫面上的片長與實際可播長度不同，屬預期。
3. `seo.og_image` 改成相對路徑；前端在假資料模式組 `og:image` 時要自行補上主站網址（或略過），這是假資料專屬情況。
4. 合成圖都是單色小圖，版面尺寸由 API 的 `width`／`height` 決定。
5. 只匯出各列表第 1 頁、分類／標籤總覽（不含 `?type=` 的分頁列表）。前端需要分頁或分類列表情境時，可另以 `app/resources/contracts/public-api-v1/samples/` 的手寫樣本補足。
6. 本工具依賴契約對 `Image.url`、`og_image`、`audio_url` 不限定絕對網址；若日後契約加上 `^https?://` 之類的限制，假資料會在再驗證時失敗，需要一併調整。
