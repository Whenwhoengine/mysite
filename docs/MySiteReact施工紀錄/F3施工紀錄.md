## 3. 實作摘要

- **結構**：v1 §6.2。頁面（`src/pages`）只接取資料函式與畫面元件；`_app` 依 `shell／head／view／error` 組成每一頁。
- **資料層**（`src/server`）：v1 §6.3、定案 §4.9。環境變數 `MYSITE_DATA_MODE`、`MYSITE_API_ORIGIN`、`MYSITE_API_TIMEOUT_MS`、`MYSITE_PUBLIC_ORIGIN`、`MYSITE_SITE_NAME`（名稱由施工者定稿，未沿用 `CONTENT_API_BASE_URL`）。逾時**不給預設值**，真資料模式未設定即啟動失敗（D13c 待裁定）。正式守門以 `src/instrumentation.ts` 在啟動時檢查。
- **受保護元件**：v1 §6.4＋`SiteLink`（定案 §4.4）＋內建靜態頁首頁尾、`<head>`、開發模式資料來源提示（定案 F3 第 8 步）。外觀集中在開放區 `src/components/safe-styles.ts`，設計可改外觀、改不到行為與掛鉤。
- **Tailwind v4 主題**：`@theme` 五組語意變數，值全部取自 mysite `app/resources/css/tokens.css` 與各元件 CSS；`--duration`、`--color-focus` 名稱沿用（mysite E2E 讀取）。與現行 Blade 在 390、768、1440 三種寬度並排比對，版面一致（差異只在示例資料與合成圖）。
- **規則文件**：`AI_RULES.md`、`AGENTS.md` 逐字取自定案 §5.1；`CLAUDE.md` 定稿受保護路徑宣告區塊格式（`<!-- protected-change:begin -->` 與 `<!-- protected-change:end -->` 之間逐行 `- 路徑`）。

## 5. 零啟動自改寫封條（FE-19）與發現

- 正式建置後、短暫啟動 `next dev` 後，`git status --porcelain` 皆為空；`tsconfig.json` 未被 Next.js 補寫。
- **發現**：Next.js 16.4 的 `next dev` 偵測到 AI 代理時，預設會自動建立或改寫 `AGENTS.md`（`node_modules/next/dist/server/lib/generate-agent-files.js`）。這會改到受保護的 `AGENTS.md`，使它與 `AI_RULES.md` 不一致，也違反 FE-19。已在 `next.config.mjs` 設官方選項 `agentRules: false` 關閉；`CLAUDE.md` 註明不可移除。實測時自動產生的 `AGENTS.md` 是施工者自己這次跑出來的檔，已刪除後改用正式全文。

## 8. 與 Blade 的差異與其他發現

- 頁尾一律有「隱私說明」（選單沒有時補上），依掛鉤清單 `layout.footer-privacy-link`。
- 站內連結一律相對路徑（定案 §4.4）。
- Next.js 在 `<head>` 標籤加 `data-next-head=""`：mysite 現行 E2E 以 `/<title>([^<]*)<\/title>/` 比對會失配；F6 依 v1 §6.5 第 2 點改為 DOM 查詢時一併處理。
- Next.js 會先把 `/articles/%2e%2e` 正規化成 `/`（和 nginx 一樣），資料層看不到 `..`；E2E 以原樣送出的路徑驗證 API 只收到 `/api/v1/` 之下、不含 `..` 的請求。
- 網址百分比編碼殘缺時 Next.js 判 400；錯誤頁保留 400（同 Blade），不改成 500。
- 樣本集測試抓到一處施工者自己的遺漏：列表 `data` 最多 12 筆，已補。
- gitleaks 把 `contracts/SOURCE.json` 裡「檔名: SHA-256」誤判成金鑰（提交 b954c80）；已推送的歷史不改寫，改以 `.gitleaksignore` 只豁免這一筆指紋，並把格式改為 `path`／`sha256` 欄位。
