  1. 頁碼上限 1000（`PublicContentInput`）；原單元測試把 9999 當合格是錯的期望值，已改正。
  2. 陣列型網址參數依 PHP 規則（`page[]`、分類標籤的 `type[]` → 404；搜尋的 `q[]`、`type[]` 視同未提供）。
  3. GET／HEAD 以外的方法回 405「不支援這個操作。」，不帶 `Allow`（同 Blade 的 `ErrorRenderer`）。
  4. 麵包屑標題依顯示寬度截斷（`Str::limit`＝`mb_strwidth`／`mb_strimwidth`）；原單元測試以字數截斷是錯的期望值，已改正。
  5. 寬字元表改為 PHP 8.5.12 逐碼位實測的 123 段（補 emoji、CJK 擴充 B 以後、全形字等）；與 PHP 隨機比對 16,000 例零差異。
  6. 「沒有內文」比照 `SafeContent::isEmpty`（`strip_tags` 逐行移植）。
  7. 假資料模式 `/search?page=2`（沒有字詞）回 200，不再 404。
  8. 錯誤訊息文字比照 Blade（頁碼或 slug 不合格「找不到這個內容。」、沒有對應路由「找不到這個頁面。」；`CONTENT_MODEL_UNSUPPORTED` 的 503 訊息）。
  9. `MYSITE_API_TIMEOUT_MS` 上限（見第 9 節）。
  10. 網站資訊取不到時，首頁標題不再混用兩個站名。
  11. canonical 比照 `PageMeta::canonicalUrl` 一律接在主站網址之後（必定同源）；`og:image` 只收單一 `/` 開頭路徑或 https 網址，`//` 開頭不收。
  12. 瀏覽器端自行畫出的錯誤頁不捏造請求編號（不顯示），站名取第一次載入時的內建站名。
- **與 Blade 仍有的差異**：
  - `OPTIONS`：Next.js 在頁面程式之前就回 400、空內文（實測）；Blade 回 200＋`Allow: GET,HEAD`。本專案不得用 middleware，留給 F6 gateway 在 next 模式處理。
  - 瀏覽器端錯誤頁沒有 `error_view.request-id` 掛鉤（沒有伺服器請求，不捏造編號）。
  - Laravel 的 `TrimStrings` 會另外去掉 U+200B、U+200E，JavaScript 的 `trim()` 不會（審查範圍外，未改）。
  - Next.js 不保留 `page=1&page[]=2&page=3` 這類交錯鍵的順序，這一種寫法無法完全比照。
