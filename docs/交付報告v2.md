## 5. 未驗證或有限制的部分

- 沒有任何真實主機上的驗證：HTTPS 憑證與續期、主機重啟、告警送達、異地備份、正式秘密隔離、30 天可用性觀察。
- YouTube 與音訊的外部實際播放：只驗了嵌入契約（iframe 網址、Range／206、MIME），實際播放要在 staging 用瀏覽器確認。
- WordPress 外掛弱點資料來自 WPVulnerability 公開 API，該服務沒有明確的服務條款或保證。Wordfence 的資料需要免費 API 金鑰，須由委託人申請。
- 第三方或 WordPress 固有行為，已記錄、未修改：
  - Two Factor 外掛 0.17.0 以明文存放 TOTP 秘鑰。
  - uploads 內的檔案知道網址就能讀，包含草稿使用的媒體。
- 金鑰圈 promote 之後最晚 24 小時內要 retire（暫定）。目前由文件與輪替紀錄管理，程式不會自動強制。
- edge 網路新增了固定位址與動態分配範圍。既有環境第一次套用時，要先 `docker compose down`（不加 `-v`，資料卷保留）才會重建網路。目前沒有正式主機，所以不受影響。
- 合併後 release.yml 的自動發布預設關閉，因為推送 GHCR 可能佔用付費額度；委託人設定 `MYSITE_AUTO_RELEASE=true` 才會啟動。main 上已實際確認 release 被開關擋下（skipped）。

## 7. 施工中發生的事故與揭露

v1 已揭露的事件：測試誤清開發資料庫、E2E 截圖拍到開發密碼、gateway 過期 IP、子代理刪除自建測試內容、子代理更名檔案後還原、預設文章改草稿、清除 Docker 建置快取。詳見 `docs/交付報告.md` 第 7 節。

v2 新增：

| 事件 | 影響 | 處置 |
|---|---|---|
| main 上的 CI（run 41973428482）發現 WordPress 排程競態：排程與 wp-jobs 執行同時發生時，新的發布事件被覆寫而遺失 | 若發生在正式站，排程文章會停在「已排程」不發布 | wp-jobs 每輪執行排程補救（補排、補發）；新增回歸契約測試，CI 通過 |
| 在下撰寫的治理檢查（CLD-03）在 main 上誤判，要求執行分支必須等於工作分支 | 只影響 main 的 CI 結果 | 修正判斷 |
| 在下撰寫的代理信任測試在 CI 失敗（run 41981570258）；本機因設定值相同而碰巧通過 | 只影響測試 | 改為走正式設定路徑，並以不同設定值重跑確認 |
| 子代理在 VM 的 testing 環境實跑金鑰輪替，該環境的金鑰與 APP_KEY 因此已換過 | 只在 VM，不進 Git；CI 每次都是全新環境 | 已記錄；需要時重建 testing 環境即可 |
| 開發環境為套用新網路設定，執行過一次 `docker compose down`（不加 `-v`） | 容器與網路重建，資料卷保留 | 重建後 doctor 全過 |
| 既有契約測試 `events_reconcile_recovers_after_hook_failure` 會永久刪除「該測試當次建立」的一篇文章，以驗證刪除事件的對帳 | 只在 testing 或開發環境，只刪測試自己建的內容 | 屬既有測試設計，照實揭露 |
