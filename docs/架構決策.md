# 架構決策紀錄（ADR）

本檔記錄施工中做出的工程決策。v5 已固定的選型（WordPress＋Laravel 13＋PHP 8.5＋MySQL 8.4＋Nginx＋Compose）不在此重新討論，只記實作層決策與偏離理由。

## ADR-001 monorepo 路徑契約
- `app/` 是 Laravel 專案根（PHP 類別在 `app/app/`），`wp/` 是 WordPress 自製程式（外掛、mu-plugins、ACF JSON、設定模板、測試）。
- WordPress 核心、第三方外掛 zip、`vendor/`、`node_modules/` 不進 Git；建置時依 `infra/versions.env` 的 hash 取得與驗證。

## ADR-002 服務拓撲
```
瀏覽器 → gateway(Nginx, 依 host/port 路由)
          ├→ app-web(Nginx, Laravel public/) → app-php(FPM :9000)
          └→ wp-web(Nginx, WP 核心靜態檔＋uploads) → wp-php(FPM :9000)
app-worker（queue:work）、app-scheduler（schedule:work，單一實例）
wp-jobs（WP-CLI：到期排程、outbox 投遞、每分鐘對帳；flock 防重入＋心跳檔）
mysql（mysite_wp／mysite_app 兩庫兩帳號；不發布埠）
test-runner（只在 dev／CI profile）
```
- Nginx 與 FPM 使用一致路徑：Laravel `/var/www/app/public`，WordPress `/var/www/wp`。
- 開發入口只綁 `127.0.0.1`：主站 `127.0.0.1:8080`、CMS `127.0.0.1:8081`。正式由 `compose.prod.yml` 只發布 80／443。
- Laravel→WP 公開讀取走容器內固定來源 `http://wp-web:8080/wp-json/site-content/v1`（v5 允許的固定私網例外）；帶服務憑證的預覽讀取走 `https://wp-web:8443/...`，由本案測試 CA 簽發的伺服器憑證，Laravel 只信任該 CA 檔，不關閉 TLS 驗證。

## ADR-003 開發模式以 bind mount 掛原始碼
- `compose.dev.yml` 將 `app/` 與 `wp/plugins/site-content` 等掛入容器，便於雲端會話即時修改；`compose.ci.yml`／`compose.prod.yml` 一律使用建置好的映像，不掛原始碼。
- Composer／npm 在 `tools` 服務（同 PHP 8.5.12 映像＋Composer）執行，保證平台需求以實際 PHP 版本解析。

## ADR-004 映像 registry 備援
- Docker Hub 匿名拉取在 Claude VM 出現 429。改由 `BASE_IMAGE_REGISTRY` 參數選擇 `docker.io/library` 或 `public.ecr.aws/docker/library`（Docker 官方映像在 ECR Public 的發布處）。
- 兩者以**相同 digest** 引用；本次六個基底映像 digest 均實測相符。digest 不同即建置失敗，不會悄悄換內容。

## ADR-005 Claude VM 內 Composer 下載
- 雲端代理對 `api.github.com` 的 zipball（Composer dist）連線逾時；Composer 會自動改用 git source 下載，速度慢但內容仍受 lockfile 的 source reference 固定。
- VM 內安裝採 `--prefer-source` 避免逐一等待逾時；GitHub Actions 乾淨 runner 使用預設 dist。兩者都以同一個 `composer.lock` 為準，CI 另跑 `composer validate --strict`、`composer audit`、`composer check-platform-reqs`。

## ADR-006 秘密與 `*_FILE` 契約
- 開發／測試秘密由 `scripts/cloud/bootstrap.sh` 首次產生於 `.runtime/secrets/<env>/`（目錄 0700、檔案 0600），重跑不覆寫；資料卷已存在但秘密遺失時拒絕繼續並標記需修復。
- Laravel 在 `bootstrap/app.php` 之前由 `app/bootstrap/secrets.php` 讀取 `*_FILE`（去除結尾換行、拒絕空值、拒絕權限過寬、拒絕缺檔）；production 缺必要秘密即拒絕啟動。WordPress 由 `wp/config/wp-config.template.php` 以同樣規則讀檔。
- WordPress 容器只拿得到 WP 自己的 DB 密碼、salts、事件 HMAC 金鑰、預覽簽章金鑰；Laravel 容器拿不到 WP DB 密碼，反之亦然。

## ADR-007 內容快取與可見性租約
- 正文快取（預設 300 秒）與可見性證明（預設 30 秒，硬上限 60 秒）分開存放。供應正文前必須持有未過期的可見性證明；過期就同步向 WP 重新確認；確認失敗回 503，不回舊正文。
- 列表、搜尋、分類、首頁、RSS、sitemap、選單的快取 TTL 不得超過可見性期限，並以內容世代號（generation）在收到事件時立即失效。
- 不設任何 stale fallback。

## ADR-008 事件與預覽票券格式
- 事件：HMAC-SHA256，簽署字串 `delivery_timestamp + "\n" + event_id + "\n" + raw_body`，header `X-Mysite-Key-Id`、`X-Mysite-Timestamp`、`X-Mysite-Signature`（小寫 hex）。時差窗 300 秒。
- 預覽票券：`base64url(header).base64url(claims).base64url(HMAC-SHA256)` 的緊湊格式，header 固定 `{"alg":"HS256","typ":"mysite-preview"}`，claims 含 `iss`、`aud`、`typ`、`ctype`、`cid`、`sid`、`rev`、`iat`、`exp`、`jti`、`sub`。預覽金鑰與事件金鑰分開。Laravel 端以 DB 唯一鍵原子消耗 `jti`。

## ADR-009 安全掃描工具
- 依賴：`composer audit`、`npm audit --omit=dev --audit-level=high`。
- 秘密：本案 `scripts/ci/secret-scan.sh`（規則式掃描 Git 追蹤檔與證據目錄），CI 另以鎖定 digest 的 gitleaks 映像掃描完整歷史。
- 映像：CI 以鎖定 digest 的 Trivy 映像掃描建置出的映像；掃描無法執行時記為未完成，不是無漏洞。

## ADR-010 HTML 安全
- Laravel 以 `symfony/html-sanitizer` 建立唯一 allowlist sanitizer，輸出包成 `App\Support\Html\SafeContent`；只有 `resources/views/components/rich-content.blade.php` 允許 `{!! !!}`，`scripts/ci/check-blade-raw.sh` 阻擋其他位置。
- YouTube 播放器以驗證過的 11 碼 ID 產生 `youtube-nocookie.com` 嵌入，點擊後才載入。

## ADR-011 購物車
- 購物車只存在 Laravel Session（database driver），不建立 `cart_items` 表，避免兩個權威來源（v5 §10.2 明確簡化決策）。

## ADR-012 時區
- 框架與資料庫儲存一律 UTC（`config/app.php` 的 `timezone` 固定 `UTC`、MySQL `--default-time-zone=+00:00`）；`APP_TIMEZONE`（預設 Asia/Taipei）映射到 `mysite.display_timezone`，只用於畫面顯示。
- WordPress 編輯端使用 `timezone_string=Asia/Taipei`；API 一律輸出 UTC ISO 8601。這樣跨日排程與 API 邊界不會因伺服器時區而偏移。

## ADR-013 映像建置不經 Compose bake
- Docker Compose v5 的 build 改走 buildx bake，對 host 網路與外部檔案需額外 `--allow` 授權；為了讓 Claude VM（需經代理）與 Actions 用同一條路徑，映像統一由 `scripts/lib/build.sh` 以 `docker build` 建置，Compose 只引用映像 tag。

## ADR-014 測試庫隔離
- PHPUnit 一律連 MySQL 測試庫 `mysite_app_test` 或 `mysite_app_test_<後綴>`（`tests/TestCase.php` 強制檢查名稱），不使用 SQLite；並行開發以不同後綴隔離。
