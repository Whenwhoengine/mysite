# 故障判斷手冊（維護者）

適用：開發（`mysite-dev`）、測試（`mysite-test`）與日後的 staging／production（`mysite-staging`／`mysite-production`）。所有指令在雲端 Linux 主機或 Claude 雲端 VM 執行，不需要本機工具。

## 0. 先看整體

```bash
bash scripts/cloud/doctor.sh --env=development
```
`doctor` 會逐項回報 PASS／FAIL 並寫入 `.runtime/evidence/doctor-<env>.json`（去秘密化）。依失敗項目對照下表。

| doctor 項目 | 代表什麼 | 先查 |
|---|---|---|
| SERVICES | 有容器沒在執行或健康檢查失敗 | `bash scripts/cloud/dev.sh compose ps`，再看該服務 log |
| APP-LIVE | Laravel FPM 或 app-web 不通 | app-php、app-web log；`/healthz` 不碰 DB |
| APP-READY | Laravel 無法連 DB 或缺 framework 資料表 | mysql 健康、`dev.sh artisan migrate:status` |
| CMS-HEALTH | WordPress／site-content 外掛不可用 | wp-php log、外掛是否啟用 `dev.sh wp plugin list` |
| INF-01-* | Web PHP 版本或安全設定與鎖定值不符 | 映像是否重建、`infra/php/security.ini` |
| WP-CORE | WordPress 核心檔被改動 | 重建 wordpress 映像；核心不應在容器內被修改 |
| INF-02-* | DB 跨庫權限或埠暴露異常 | `infra/mysql/init/`、Compose `ports` |
| INF-03／INF-04 | 敏感檔可下載或 uploads 可執行 | `infra/nginx/` 設定是否被改 |
| GW-LOGIN-LIMIT | 某個登入路徑變體（例如 `/admin/login/`、`/wp-login.php`）可繞過 gateway 登入限流，或 `/index.php/<路徑>` 別名沒被擋 | 明細在 `.runtime/evidence/gateway-login-limit-<env>.txt`；查 `infra/nginx/gateway/*/gateway.conf.template` 的登入 location 與 `location ^~ /index.php/`，改完要重建 gateway 映像 |
| JOBS | wp-jobs 心跳逾時、worker／scheduler 停止 | 見第 3 節 |

## 1. 讀 log（已去識別的 JSON）

```bash
bash scripts/cloud/dev.sh compose logs --tail=200 app-php
bash scripts/cloud/dev.sh compose logs --tail=200 wp-jobs
```
每行含 `timestamp`、`service`、`environment`、`level`、`event`、`request_id`、`error_code`。訪客回報錯誤頁上的「請求編號」可用 `grep <request_id>` 找到同一請求。log 不會有密碼、cookie、票券；若看到，視為 SEV1 事故（見 `docs/runbooks/事故處理.md`）。

## 2. 內容相關

| 症狀 | 可能原因 | 處置 |
|---|---|---|
| 所有內容頁 503「內容暫時無法讀取」 | Laravel 連不到 WordPress，或可見性證明到期且 WP 不可達（這是刻意的安全行為） | 恢復 wp-php／wp-web；不要為了「先有畫面」關閉可見性檢查 |
| 某篇已撤下文章仍可見 | 不應超過 60 秒；超過即為 SEV2 | 查 `content_event_receipts` 與 WP outbox：`dev.sh wp site-content outbox list --state=dead` |
| 事件一直進死信 | 簽章金鑰兩端不一致、Laravel 不可達 | 確認兩端 `content_event_hmac_key` 同一檔；修好後 `dev.sh wp site-content outbox replay <event_id>`。有金鑰圈時改比對 `dev.sh wp site-content keyring event-hmac` 與 `dev.sh artisan mysite:keyring event-hmac`（只列 key ID 與狀態），兩者須與 `content_event_hmac_keyring` 一致；死信的 `last_error` 為 HTTP 401 且剛 retire 過舊 key 時，重播即會以新 key 簽章 |
| 預覽顯示「預覽連結已失效」 | 票券過期（預設 10 分鐘）、已使用過、內容已刪除或服務帳號密碼不符 | 回編輯器重新按預覽；服務帳號問題用 `scripts/ops/rotate-secrets.sh --kind=wp-service` |

## 3. 排程與背景工作

- **wp-jobs**：每 30 秒執行 WP 到期排程、outbox 投遞、每分鐘對帳；心跳檔 `/tmp/mysite-wp-jobs/heartbeat`。停止時排程文章不會發布、事件不會送出（內容可見性仍會在 30 秒內由 Laravel 主動確認）。
- **app-worker**：處理 `content`、`default` 佇列；`dev.sh artisan queue:failed` 查失敗工作，修正後 `queue:retry`。
- **app-scheduler**：`schedule:work` 單一實例；心跳寫入快取 `mysite:scheduler:heartbeat`。

## 4. 重建與恢復（不毀資料）

```bash
bash scripts/cloud/session-start.sh          # 只恢復服務
bash scripts/cloud/up.sh --env=development   # 啟動並等待就緒
bash scripts/cloud/bootstrap.sh --env=development   # 冪等補缺；不重設資料、管理員或金鑰
```
- 資料卷存在但秘密遺失時，bootstrap 會停下並標記 `.runtime/state/<env>/repair-needed`，**不會**隨機換密碼。請依 `docs/runbooks/秘密輪替.md` 處理。
- 禁止對 staging／production 執行 `docker compose down -v`、`migrate:fresh`、`docker system prune --volumes`。

見 `docs/runbooks/備份與還原.md`：`scripts/ops/backup.sh`、`scripts/ops/restore-check.sh --target=isolated`（永遠還原到隔離環境驗證）。
