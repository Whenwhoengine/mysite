# 秘密輪替手冊

> 對應：規劃書 v5 §13.7、附錄 D.3；設定目錄 `docs/設定目錄.md`。每次輪替都需要核准參照（`--approved-plan=`），新值只寫入秘密檔（0640、群組 33），**從不輸出**；紀錄只含種類、階段、時間與結果（`state/rotations.jsonl`）。
> 輪替與部署互斥（共用部署鎖），進行中會看到 `LOCK_BUSY`。

## 1. 一般命令

```bash
cd /srv/mysite/platform
bash scripts/ops/rotate-secrets.sh --env=production --kind=<種類> --approved-plan=<核准參照> [--phase=<階段>]
```

development 也可用，但必須明示：`--env=development --allow-development`（作用於 `.runtime/secrets/development` 與 `mysite-dev`）。

## 2. 各種類

| 種類 | 程序（腳本自動分段） | 失敗時 | 影響 |
|---|---|---|---|
| `app-db`／`wp-db` | 確認目前密碼可登入 → `ALTER USER … RETAIN CURRENT PASSWORD`（新舊都可登入）→ 換秘密檔 → 重建相關容器 → 以新密碼登入＋應用健康檢查 → `DISCARD OLD PASSWORD` | 原密碼設回主要並撤銷新密碼、秘密檔與容器回原狀（exit 50 `VERIFY_FAILED_REVERTED`） | 容器重建期間短暫中斷 |
| `wp-salts` | 換 8 組 salts → 重建 wp-php／wp-jobs → 驗證；上一組保留供 `--phase=revert` | 自動回到原 salts | **所有 WP 登入失效**，需事先公告 |
| `wp-service` | 先發行新 Application Password → 換秘密檔 → 重建 Laravel → 以新密碼呼叫 WP `users/me` 實測 → 撤銷舊密碼 | 刪除新密碼、回到原值 | 無（雙期） |
| `event-hmac`／`preview` | `--phase=add`（新 key 只被接受）→ `promote`（新 key 簽章，舊 key 仍接受）→ `retire`（撤舊）；每階段先重建接收端（Laravel）再重建發送端（WP） | 回到上一階段；`--phase=revert` 可手動回退 | 無（雙期） |
| `app-key` | `--phase=add`（新 APP_KEY，舊 key 移入 `app_previous_keys`）→ 觀察期 → `--phase=retire` | 回到原 APP_KEY | Laravel 以舊 key 解密既有資料與 Session |

前提（未滿足時腳本 exit 20 `APP_SUPPORT_MISSING`，不做任何變更）：

- `event-hmac`／`preview`：應用程式須支援金鑰圈檔（`content_event_hmac_keyring`、`preview_signing_keyring`，每行 `<key_id> <64 hex> <active|accept>`），並在主機設定 `KEYRING_SUPPORT=yes`。目前應用只讀單一金鑰，屬待整合項目。
- `app-key`：Laravel 須支援 `APP_PREVIOUS_KEYS_FILE`，主機設定 `APP_PREVIOUS_KEYS_SUPPORT=yes`。

## 3. 不在腳本範圍、需人工依序進行的輪替

**發布簽章金鑰（雙期信任）**
1. 依《主機開通》P4 產生新金鑰（新 key_id，例如 `production-2027a`），私鑰存入 GitHub environment secret 與受控保管處，主機副本銷毀。
2. 主機：`bootstrap-host.sh --env=production --approved-plan=<參照> --trust-key=production-2027a:<公鑰檔>`（新舊公鑰並存）。
3. GitHub：更新 `RELEASE_SIGNING_KEY_ED25519`、`RELEASE_SIGNING_KEY_ID`、repository variable `RELEASE_PUBLIC_KEY_PRODUCTION`。
4. 以新金鑰完成一次部署並確認後，刪除主機上的舊公鑰檔 `config/trusted-keys/<舊 key_id>.pem`（撤銷演練：以舊金鑰簽的清單應得到 `UNKNOWN_KEY_ID`）。
疑似外洩時跳過觀察期：先 `touch state/channel-paused`，直接移除舊公鑰，再依《事故處理》檢查已發布 digest。

**部署狀態唯讀權杖（`deploy_status_token`）**：產生新值寫入秘密檔（`openssl rand -hex 32 > …`，0640、群組 33）→ 重建 app-php、app-worker、app-scheduler → 更新 GitHub environment secret `DEPLOY_STATUS_TOKEN` → 下一次部署 workflow 驗證可讀。

**restic 密碼**：`restic key add`（新密碼先存入受控保管處）→ 換 `secrets/restic_password` → 手動備份一次成功 → `restic key list` 確認後 `restic key remove <舊 key ID>`。

**MySQL root 密碼**：只供初始化與管理；以 `ALTER USER 'root'@'%'`（及 `'root'@'localhost'`）配合秘密檔更新，完成後驗證 `rotate-secrets.sh` 的 DB 種類仍可執行。

**GHCR 唯讀權杖、GitHub 唯讀權杖**：先在 GitHub 建立新權杖（最小權限）→ 換秘密檔 → `pull-release.sh --dry-run` 驗證 → 撤銷舊權杖。

## 4. 紀錄與檢查

- `state/rotations.jsonl`：種類、階段、核准參照、結果。
- `secrets/.rotation/`（0700）只在輪替進行中或雙期觀察期保存上一組值，成功或 retire 後清除；不得複製到其他位置。
- 輪替後執行 `bash scripts/deploy/preflight.sh --env=<env>` 確認秘密檔權限與服務狀態。
