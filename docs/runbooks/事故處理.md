# 事故處理手冊

> 對應：規劃書 v5 §16.2、§16.5、§15.5。本手冊是專案內部程序；對外通報、正式資料刪除、帳戶權限變更與公開說明一律由委託人或核准負責人決定。
> 個資事件的外部通報對象與時限，依當時適用法令與實際資料處理角色判斷（法規可能有已公布但尚未施行的修正），**不是一律 72 小時**；內部「立即通報負責人」是本案標準，不冒稱法定期限。

## 1. 分級與第一動作

| 等級 | 例子 | 第一動作 |
|---|---|---|
| SEV1 | 私密內容外洩、主站全面不可用、未授權部署、重大資料毀損、發布私鑰疑似外洩 | 立即限制風險、保存證據、通知負責人；必要時關閉受影響入口 |
| SEV2 | 備份持續失敗、撤下超過 60 秒、內容事件死信累積、商務完整性異常、`DEPLOYMENT_UNCONFIRMED` 持續 | 停止相關寫入／商店、啟動修復與回復評估 |
| SEV3 | 單一影音來源失效、部分頁面錯誤但無資料風險 | 降級呈現、建立修復項，避免誤報全站正常 |
| SEV4 | 小型排版或可用性缺陷 | 記錄、排入工作分支並回歸測試 |

不憑 log 片段認定攻擊者身分；不在事故中刪除可作為證據的紀錄。

## 2. 常見情境

### 2.1 未授權部署或發布私鑰疑似外洩（SEV1）
1. 停止採用 channel：`touch /srv/mysite/environments/<env>/state/channel-paused`（`pull-release.sh` 之後只記錄、不拉取、不部署）。
2. 保存證據：`state/history.jsonl`、`state/events.jsonl`、`releases/`、GitHub Actions run 紀錄與 `deploy-<env>-seq-*` release。
3. 移除可疑金鑰：刪除 `config/trusted-keys/<key_id>.pem`；在 GitHub 刪除對應 environment secret，依《秘密輪替》建立新金鑰。
4. 檢查已發布 digest：比對 history 與 release.yml 的候選版；可疑 digest 寫入 `config/revoked-digests.txt`（之後不得部署或回復到它）。
5. 需要回到安全版本時，以新金鑰簽出**新序號**回復清單（《部署與回復》§4）；移除 `channel-paused` 前須經負責人核准。

### 2.2 主站不可用（SEV1）
1. `docker compose ls`、`journalctl -u 'mysite-*' -n 200`、`bash scripts/deploy/smoke.sh --env=<env> --expected-release=<active release_id>`。
2. 若剛部署：依《部署與回復》判讀 `state/release-state.json` 的 pending／last_failure；schema 相容時以新序號回復程式。
3. 主機故障：依《主機開通》在新主機重建並還原，確認後才切 DNS；不得把開發 VM 當正式站。

### 2.3 備份失敗或過舊（SEV2）
1. `journalctl -u mysite-backup-app@<env> -u mysite-backup-wp@<env> -n 100`、`state/last-backup-*.json`。
2. 常見原因：目的地憑證失效、空間不足、MySQL 容器未執行（exit 20）、`restic check` 失敗（exit 50）。
3. 修復後手動 `backup.sh --reason=manual-after-incident`；`restic check` 失敗時不得刪除 repository，先保存現況並評估以 `restic repair` 系列指令處理（需核准）。

### 2.4 憑證即將到期（SEV2）
`mysite-certbot-renew.service` 失敗會留下 unit failed。檢查 DNS 與 port 80 的 ACME 路徑，執行 `infra/systemd/libexec/mysite-certbot-renew.sh --dry-run`，修復後再正式續期；gateway reload 前一律 `nginx -t`。

### 2.5 個資或未公開內容外洩（SEV1）
1. 限制擴散：撤下相關頁面、必要時關閉入口或暫停 channel；不刪除證據。
2. 保存必要證據（去秘密化），通知指定負責人，查明範圍（資料種類、筆數、期間、接收者）。
3. 外部通報與時限由負責人依適用法令決定；當事人權利申請依官方說明分流（查詢／閱覽原則 15 日、更正／刪除等原則 30 日，必要時依法延長）。
4. 還原任何備份後都要重套刪除紀錄（`mysite:deletion-log:reapply`），避免已刪資料復活。

## 3. 紀錄格式

每次事故建立一份去秘密化紀錄（不放 token、Cookie、完整表單或正式 dump）：

```text
事故編號／等級：
發現時間（UTC）與發現方式：
影響範圍（服務、環境、資料種類與筆數）：
時間線：
證據參照（受限位置）：
處置與回復結果（含 release ID、snapshot ID）：
對外通報決定（決定者、依據、時間；未決定填「待負責人決定」）：
防再發措施與追蹤項目：
```
