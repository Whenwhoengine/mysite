# 設定目錄（GOV-01）

分層：版控設定（本檔、`infra/versions.env`、`app/config/*.php`）→ 環境設定（`.runtime/env/<env>.env` 或主機 `environments/<env>/config/compose.env`）→ 秘密（`*_FILE`）→ 執行狀態（DB、volume、發布序號）。

`app/config/mysite.php` 是 Laravel 讀取本案自訂鍵的唯一位置；`App\Support\Config\MysiteConfig::validate()` 在啟動時驗證（測試：`tests/Unit/Config/MysiteConfigTest.php`）。WordPress 端由 `wp/config/wp-config.template.php` 讀取。

## 秘密（`*_FILE`）

| 秘密 | 檔名（`.runtime/secrets/<env>/`） | 供應對象 | 產生／輪替 |
|---|---|---|---|
| MySQL root | `mysql_root_password` | 僅 mysql 初始化 | bootstrap 首次產生；不給應用 |
| WP DB 密碼 | `wp_db_password` | mysql、wp-php、wp-jobs | `scripts/ops/rotate-secrets.sh --kind=wp-db` |
| Laravel DB 密碼 | `app_db_password` | mysql、app-* | `--kind=app-db` |
| Laravel APP_KEY | `app_key`（`base64:` 格式） | app-* | 不在重啟時生成；輪替影響加密資料與 Session |
| WP salts | `wp_salts`（8 行 `NAME=value`） | wp-php、wp-jobs | `--kind=wp-salts`（使所有登入失效） |
| 事件 HMAC | `content_event_hmac_key` | wp-*、app-* | `--kind=event-hmac`（新舊 key ID 過渡） |
| 預覽簽章 | `preview_signing_key` | wp-*、app-* | `--kind=preview`；與事件金鑰分開 |
| 事件 HMAC 金鑰圈 | `content_event_hmac_keyring`（`CONTENT_EVENT_HMAC_KEYRING_FILE`） | wp-php、wp-jobs、app-*（不給 mysql、wp-web、app-web、gateway） | bootstrap／bootstrap-host 首次以既有單一金鑰建立 `k1 <金鑰> active`（已存在不覆寫）；`--kind=event-hmac --phase=add→promote→retire` 改寫 |
| 預覽簽章金鑰圈 | `preview_signing_keyring`（`PREVIEW_SIGNING_KEYRING_FILE`） | 同上 | 同上，`--kind=preview`；與事件金鑰圈分開 |
| 舊 APP_KEY | `app_previous_keys`（`APP_PREVIOUS_KEYS_FILE`） | app-*（只給 Laravel） | 平時為空檔；`--kind=app-key --phase=add` 把舊 APP_KEY 移入、`--phase=retire` 清空 |
| WP 服務帳號 Application Password | `wp_service_app_password` | app-* | bootstrap 以 WP-CLI 建立；`--kind=wp-service` |
| 內部 CA 憑證 | `internal_ca_cert` | app-*（只信任此 CA） | bootstrap 產生；CA 私鑰只留在 `.runtime/secrets/<env>/ca/` |
| 部署狀態唯讀權杖 | `deploy_status_token` | app-*、部署 workflow（environment secret） | 只用於 `/internal/deploy-status`；不等於任何管理權限 |
| 內部診斷權杖 | `diagnostics_token` | app-*、wp-*、doctor | 只在容器內直接連線時有效；gateway 不放行 |
| wp-web 內部 TLS | `wp_internal_tls_cert`／`wp_internal_tls_key` | wp-web | 由內部 CA 簽發，SAN=`wp-web` |

規則（`App\Support\Secrets\SecretFiles` 與 wp-config 一致）：檔案必須存在、非空、其他使用者不可讀寫（0640 root:33 或更嚴）；去除結尾換行；單行秘密不得含換行；staging／production 缺任何必要秘密即拒絕啟動。

金鑰圈與舊 APP_KEY（GAP-KEYRING-01）的例外規則：

- 金鑰圈檔（`*_KEYRING_FILE`）可多行：每個非空行 `<key_id> <64 字元小寫 hex> <active|accept>`，key_id 符合 `k[0-9]{1,6}` 且不重複，恰好一把 `active`。格式不合法、缺檔或權限過寬一律拒絕啟動（Laravel：`bootstrap/secrets.php` exit 20／503、容器 entrypoint exit 20、`MysiteConfig::validate()`；WordPress：wp-config exit 20／503）。有設定 `*_KEYRING_FILE` 時不會退回單一金鑰（避免回到已撤銷的舊 key）。
- 有金鑰圈時，發送端（WP）以 active key 簽章並帶其 key ID；接收端（Laravel，以及驗預覽票券的 WP 私密端點）依 key ID 接受 active 或 accept key。沒有設定 `*_KEYRING_FILE` 時沿用單一金鑰檔（事件 key ID 為 `CONTENT_EVENT_KEY_ID`，預覽為 `k1`），與先前行為相同。
- Laravel 把金鑰圈轉成單行精簡格式匯出為 `CONTENT_EVENT_HMAC_KEYRING`／`PREVIEW_SIGNING_KEYRING`，由 `config('mysite.content.event_keyring')`／`config('mysite.preview.signing_keyring')` 讀取（可隨 config:cache 快取）。
- `APP_PREVIOUS_KEYS_FILE`：檔案可不存在或為空（表示沒有舊金鑰）；有內容時每行（或逗號分隔）一把 `base64:` 格式的 32 位元組金鑰，格式不合法或權限過寬即拒絕啟動。讀入後匯出為 Laravel 原生的 `APP_PREVIOUS_KEYS`（逗號分隔），由 `config/app.php` 的 `previous_keys`（`config('app.previous_keys')`）使用：加密一律用目前的 `APP_KEY`，解密時先試目前的 key，失敗再依序試舊 key。查核來源見 `docs/版本查核.md`。
- 狀態查詢（不輸出任何金鑰）：Laravel `php artisan mysite:keyring event-hmac|preview|app-key`、WordPress `wp site-content keyring event-hmac|preview`。`scripts/ops/rotate-secrets.sh` 每期以兩者確認實際載入的金鑰圈與秘密檔一致。
- 既有環境（建立於金鑰圈支援之前）：`scripts/lib/compose.sh` 的 `ms_ensure_derived_secrets` 會在 Compose 指令前冪等補建金鑰圈（內容等於既有單一金鑰）與空的 `app_previous_keys`；已存在的檔案一律不動。正式主機由 `scripts/deploy/bootstrap-host.sh` 補建，`scripts/deploy/preflight.sh` 檢查存在與格式。
- 版本相依：Compose 會把 `APP_PREVIOUS_KEYS_FILE` 指向空檔；金鑰圈支援之前的 Laravel 映像會把空檔視為不合法而拒絕啟動，因此主機平台（compose）更新到本版時，Laravel 映像也必須是本版以後。

## PHP 啟動設定

`infra/php/security.ini`：`session.upload_progress.enabled=0`、`expose_php=Off`、`display_errors=Off`、`log_errors=On`。不是 Laravel `.env` 設定；`scripts/cloud/doctor.sh` 經 HTTP→Nginx→FPM 讀回兩個 Web SAPI 的實際值（內部診斷端點，需內部診斷權杖，不公開 phpinfo）。
