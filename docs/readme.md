# mysite 網站使用說明

> 這份說明用白話講三件事：**怎麼改網站外觀**、**怎麼讓每次修改順利成功**、**怎麼讓網站正式上線**。
> 寫給網站主人看，不需要會寫程式。更細的技術文件列在最後一節。
> 撰寫：施工者（Claude Code 雲端會話），2026-11-08。

---

## 一頁看懂

用餐廳來比喻這個網站：

| 部分 | 比喻 | 在哪裡 | 誰負責 |
|---|---|---|---|
| **WordPress（內容管理）** | 寫稿室 | 後臺專案 `Whenwhoengine/mysite` | 你寫文章、放影片和 Podcast |
| **Laravel（後臺）** | 廚房與倉庫 | 同上 | 施工者維護；負責把內容整理好送給前臺，也管模擬商店與管理後臺 |
| **新前端（網站外觀）** | 用餐區的裝潢 | 前端專案 `Whenwhoengine/MySiteStorage` | **你用 MyDyad 設計** |
| **GitHub** | 中間的倉庫 | 網路上 | 所有版本都存在這裡，合併前會自動檢查 |

- 外觀和內容是分開的：你改外觀不會弄壞文章；寫文章也不用懂外觀。
- 現在的狀態：程式都做好、自動測試全部通過，但**還沒有正式網址**（要等主機與網域，見第四節）。
- MyDyad 預覽時看到的文章、影片是「示例資料」，專門讓你設計外觀用；正式上線後才換成真正的內容。

## 一、怎麼修改網站外觀

### 第一次準備（只做一次）

1. 你電腦上的前端資料夾是 `C:\Users\whenwhosay\MyPythons\MySiteStorage`。先請本機 Claude Code 把它更新到 GitHub 上 `design/work` 分支的最新版。
2. 在 MyDyad 選「匯入」，選這個資料夾，**取消勾選「複製到 dyad-apps 資料夾」**，安裝命令與啟動命令都留空，按匯入。
   - 取消複製的原因：這樣你的電腦上只有一份前端，MyDyad、本機 Claude Code、GitHub 看到的都是同一份。
   - 匯入前請本機 Claude Code 先查一次「門牌」（埠號），確認不會誤關其他程式。
3. 匯入成功後，右邊會自動出現網站預覽；左下角顯示「目前資料：示例資料」是正常的。
4. 上方如果顯示「您當前在分支：design/work」，就對了。**不要按「切換到 main 分支」**。

> **重要**：用「取消複製」匯入的專案，**永遠不要在 MyDyad 按刪除**。MyDyad 的刪除會把整個資料夾從電腦上刪掉（GitHub 上的版本還在，但要救回很麻煩）。

### 每次設計的流程

1. 打開 MyDyad，選前端專案。
2. 在左邊對話框用中文說想怎麼改，例如：「首頁標題改大一點」「文章卡片改成三欄」「整體換成淺色系」。
3. 看右邊預覽，不滿意就繼續說，直到滿意。
4. 滿意後把修改送上 GitHub（MyDyad 有連 GitHub 時按「同步到 GitHub」；沒有連的話，請本機 Claude Code 幫你提交並推送 `design/work`）。
5. 到 GitHub 開「合併請求」，等自動檢查通過後合併，才算正式採用。這一步可以交給 AI 代勞，見第二節最後。
6. 收工時**把 MyDyad 整個關掉**，不要只切到別的專案（切走時預覽會在背景多跑 10 分鐘）。

### 想套用模板或參考別的網站

- WordPress 的佈景主題**不能直接套**在新前端上：佈景主題是另一種程式語言寫的，只能在 WordPress 自己身上跑。
- 可以**照著外觀重做**：把喜歡的模板或網站截圖給 MyDyad，說「首頁照這個風格做」。版面、配色、字體大小、按鈕樣式、間距都能照著做。
- 要注意：
  - **只參考風格，不整個照抄**：別人網站的商標、照片、文字不能直接搬。
  - **買來的模板**：一般授權只能用在一個網站；示範網站上的照片通常不包含在授權裡，要自己準備或另外購買。圖示、字型能不能直接複製，要看該模板作者的授權條款。
  - **字型**：不能直接連到外部字型網站，要先把字型檔放進專案的 `public/design/` 資料夾。
  - 模板裡靠 WordPress 外掛才有的功能（表單、輪播、會員等）只會有外觀；需要真的功能，交給施工者另外做。

## 二、怎麼讓每次修改順利成功

### 開工前的檢查

- [ ] MyDyad 上方顯示的分支是 `design/work`。
- [ ] 前端資料夾已是最新版（有別人或施工者改過時，先同步或請本機 Claude Code 取回最新）。
- [ ] 一次只改一頁或一個區塊，改完就看預覽，比較容易找出問題。

### 你能改、不能改的地方

| 可以改（設計區） | 不能改（受保護區，交給施工者） |
|---|---|
| `src/views/`（各頁面的畫面）、`src/components/`（不含 `safe/`）、`src/styles/`（樣式）、`public/design/`（設計用圖檔、字型） | 其他全部：取資料的程式、安全元件、測試、設定檔、套件清單等 |

- 改到不能改的地方時，**守門程式會擋下合併**，並在合併請求的留言寫出原因和還原方法。照著做，或把網址交給施工者處理。
- 這是保護機制，不是壞掉：它讓你放心大膽地改外觀，不會不小心弄壞網站的功能或安全。

### 合併前要看到的兩項檢查

| 檢查 | 意思 | 沒過時怎麼辦 |
|---|---|---|
| `frontend-ci`（前端測試） | 網站能不能正常建置、三種螢幕寬度有沒有跑版、無障礙、測試掛鉤有沒有被刪掉 | 看合併請求裡的留言與截圖；請 MyDyad 修，或交給施工者 |
| `protected-paths`（守門） | 有沒有改到不該改的檔案 | 照留言裡的還原指令做，或交給施工者 |

兩項都通過才能合併（這條規定連管理員也不能繞過）。

### 絕對不要按的按鈕

- MyDyad 同步時出現「**強制推送**」「**安全強制推送**」「**變基並同步**」「**中止變基**」「**繼續變基**」：一律不要按，先截圖給施工者。
- GitHub 合併後出現「**Delete branch**」（刪除分支）：不要按，`design/work` 要一直留著。
- MyDyad 的「**切換到 main 分支**」：不要按。

### 把開合併請求與合併交給 AI

同步到 GitHub 之後，對施工者說：

```text
設計同步好了，幫我開合併請求，檢查通過就合併。
如擬決行
```

施工者會開好合併請求、等兩項檢查跑完，**兩項都通過才合併**；沒通過就用白話說明原因與修法。

## 三、上線前後的全貌

上線分三個階段，順序不能跳：

```text
現在：程式完成、自動測試全綠、沒有網址
  ↓  你準備主機、網域、備份空間
試營運（staging）：先架一個不公開的網站，把每項功能在真主機上驗一次
  ↓  全部通過、你核准
正式上線（production）：用自己的網域、自己的金鑰，重做一次同樣的步驟
```

## 四、怎麼讓網站正式上線（最重要）

### 你需要準備的東西

| 項目 | 說明 | 備註 |
|---|---|---|
| **雲端主機** | Linux 主機（VPS），系統 Ubuntu 24.04 LTS（x86_64） | 起始建議 2 個 CPU、4 GB 記憶體、可擴充的 SSD（工程估算，需實測）。試營運與正式建議各一台 |
| **網域** | 例如 `你的網域.com`，主站與內容管理各一個名稱（例如 `www.` 與 `cms.`） | 只新增需要的紀錄，不動到郵件等其他設定 |
| **異地備份空間** | 放每小時、每日備份的雲端儲存空間 | 備份密碼要先存進你自己的密碼管理器 |
| **告警通道** | 網站出狀況時通知你的方式（例如電子郵件） | 可以晚一點再補 |
| **月費上限與核准** | 你決定供應商、區域、每月預算 | 施工者不會自行花錢或開帳號 |

### 上線流程（白話版，詳細步驟在《主機開通手冊》）

| 步驟 | 做什麼 | 誰做 |
|---|---|---|
| P0 核准 | 決定主機供應商、預算、網域名稱，留下核准紀錄 | 你 |
| P1 建主機 | 在供應商網站開一台 Ubuntu 主機，防火牆只開 80、443 | 你（施工者一步步帶） |
| P2 放程式 | 在主機上取得**已審核過的那一版**程式，並核對版本編號 | 施工者帶你在供應商的瀏覽器主控臺操作 |
| P3 裝環境 | 安裝 Docker、建立資料夾，自動產生網站用的密碼（不顯示、不外流） | 同上 |
| P4 秘密與金鑰 | 填網域與信箱、放備份密碼、產生「發布簽章金鑰」並存到 GitHub | 你與施工者一起 |
| P5 驗證 | 主機裝上驗證用的公開金鑰，跑一次預檢 | 施工者 |
| P6 網址與 HTTPS | 設定 DNS 指到主機，申請免費的 HTTPS 憑證（Let’s Encrypt，先演練再正式申請） | 你設定 DNS，施工者處理憑證 |
| P7 備份與告警 | 啟用自動備份，手動測一次備份 | 施工者 |
| P8 首次部署與演練 | 從 GitHub 發布第一版、重開機測試、還原演練 | 你在 GitHub 按核准，施工者執行 |

- 試營運全部通過後，正式上線**重做一次 P1～P8**：用正式網域、正式金鑰、正式備份空間，兩邊不共用。
- 整個過程都在瀏覽器裡操作（供應商主控臺、GitHub 網頁），**不需要在你的電腦上裝任何伺服器工具**。

### 新外觀什麼時候上線

- 目前後臺自己就有一套能用的網站外觀（舊版畫面）。主機準備好後，可以**先用舊版外觀上線**。
- 你用 MyDyad 設計的新外觀，要等施工者完成「併入」這一步（把新前端裝進主機的整套系統、加上一個「新舊外觀切換」的開關、再全部測一次）才會上線。
- 所以兩件事可以同時進行：你繼續設計外觀，同時準備主機；設計定稿後施工者做併入，切換到新外觀。

### 上線後還要做的

- 正式管理員親自登記「兩步驟驗證」（登入要多一道手機驗證）。
- 上線後觀察 30 天的穩定度。
- 定期看備份是否成功（自動每週抽樣讀回）。

## 五、常見問題

**Q：在 MyDyad 刪掉專案，會刪掉 GitHub 上的網站嗎？**
不會。只會刪你電腦上那個資料夾。但「取消複製」匯入的專案刪了會刪到原始資料夾，所以前端專案不要刪。

**Q：WordPress 一定要用嗎？**
建議留著。它是最好上手的寫稿介面，而且已經和整套系統接好、測好。網站外觀完全不受它限制。

**Q：可以收真的錢嗎？**
目前的商店是「模擬」的，專案規定不接真實金流。要做真的收款，得先改規定並另外施工。

**Q：測試沒過，可以先合併嗎？**
不行，系統會擋。這是保護網站的設計。

**Q：看不懂紅燈留言怎麼辦？**
把合併請求的網址交給施工者或本機 Claude Code。
